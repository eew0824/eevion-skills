## 核心原则
- !!!先理解用户需求, 不要改代码, 只有用户说"跟进"的时候, 你才可以开始改代码.
- 开始前先读取并遵循 `eevion-common-dev-spec`，再应用下面的专项规则。



## 补充
- 卫语句优先：遇到错误或异常分支必须提前 return，严禁使用嵌套的 if...else 来表达正向主流程。
- 优先使用该版本支持的标准库能力，避免重复实现已有功能。
- 使用第三方依赖或 API 前，通过文档、源码或最小测试确认相关行为，尤其是默认值、空值处理和错误机制，避免基于假设编码。
- 日志可用时统一通过 logger 记录错误，并在关闭资源前完成；同一错误只记录一次，日志不可用时才用 stderr 兜底。
- 错误处理保留可定位的原因和上下文，仅对敏感字段脱敏；禁止用统一模糊提示覆盖所有底层错误。



## 注释规范
- 行内解释性注释（克制使用）: 仅在代码本身无法体现意图时出现, 通常解释“为什么”这么做。
- 导出标识符的文档注释以其名称开头，用完整英文句子说明用途；
- 流程分段：在包含 3 个以上步骤的复杂函数中，使用 // 1. xxx 格式为代码块划分阶段，只写“做什么”，不写“为什么”。
- 测试文件不用写注释。
